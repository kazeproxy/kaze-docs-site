    协议与传输¶

    协议、传输、安全层都在面板节点编辑页设置，kaze 自动同步。这里说几个要点。

    支持的协议¶

    图例：

    • 支持
    • 不支持
    协议 UDP 说明
    Trojan
    SOCKS5 可开 TLS（Xboard 后台的 SOCKS 节点没有 TLS 选项）；只核对密码（面板订阅里用户名和密码都是 UUID，本地模式用户名可以是名字）
    HTTP 代理 可开 TLS；不转发 UDP；认证同 SOCKS5
    Shadowsocks 经典 AEAD 和 2022 都支持
    VLESS 支持 Vision 流控
    VMess
    Hysteria2 基于 QUIC，必须配 TLS 证书
    TUIC v5 基于 QUIC，必须配 TLS 证书
    AnyTLS
    Mieru TCP 或 UDP 传输，见 Mieru
    Naive 必须开 TLS、传输选 TCP，只支持 HTTP/2（不支持 QUIC）；见下方 Naive
    Snell v1 ~ v3，UDP 需要客户端用 v3；见下方 Snell

    Shadowsocks 支持的加密：aes-128-gcm、aes-192-gcm、aes-256-gcm、chacha20-ietf-poly1305、xchacha20-ietf-poly1305、2022-blake3-aes-128-gcm、2022-blake3-aes-256-gcm；以及 mihomo 扩展的 aegis-128l、aegis-256、aez-384、deoxys-ii-256-128、ascon128、ascon128a、lea-128-gcm、lea-192-gcm、lea-256-gcm、rabbit128-poly1305（这些只有 mihomo / Clash.Meta 类客户端支持）。

    Xboard 的「加密算法」下拉框里没有的，直接输入算法名即可，面板会原样下发给节点。

    支持的传输¶

    tcp、ws（WebSocket）、httpupgrade、grpc、h2、xhttp（SplitHTTP），以及 QUIC（Hysteria2 / TUIC 专用）。

    多路复用¶

    面板里给节点开了多路复用的，客户端用 smux / yamux / h2mux 都能连。

    TCP Brutal：面板多路复用设置里打开 Brutal，填上行和下行带宽（Mbps）。上行是节点收的速率，下行是节点发的速率。客户端请求 Brutal 时，节点按双方较低的速率给这条连接换上 Brutal 拥塞控制。条件：

    • 节点是 Linux，并已加载 tcp-brutal 内核模块；没有加载时，请求 Brutal 的客户端会被拒绝，并告知原因，启动日志也会提示。
    • 传输是 TCP、WebSocket、HTTPUpgrade 这类一条连接只属于一个会话的；gRPC / H2 / XHTTP 多个会话共用一条连接，不适用。
    • 上行和下行都要填；只填一个时，请求 Brutal 的客户端会被拒绝，日志提示。

    REALITY¶

    节点安全选 REALITY，不需要域名和证书。可用于 VLESS、Trojan、AnyTLS、VMess、SOCKS5、HTTP；传输只能是 tcp、grpc、h2、xhttp。面板里要填：

    面板字段 示例 说明
    伪装域名 www.microsoft.com 一个支持 TLS 1.3 的大网站。不是你的用户的访问会被原样转给它，探测者只会看到这个网站
    伪装站点端口 443 伪装网站的端口，一般 443
    私钥 / 公钥 点生成按钮 Xboard 点私钥输入框右边的钥匙按钮，私钥和公钥一起生成。私钥给节点，公钥给客户端
    Short ID 6af819e1 最多 16 位、偶数位的十六进制，点刷新按钮生成或自己填一个

    这些值由面板下发给节点，节点上不用再配。

    面板没有生成按钮时，可以在服务器上运行 kaze -reality-keypair 生成一对，PrivateKey 填私钥、PublicKey 填公钥。

    Note

    REALITY 能与官方客户端互通。默认情况下，节点给自己客户端的握手回包，形态和伪装站点的一致（reality_mirror，见配置项速查表）。伪装站点会触发 HelloRetryRequest 时不做模仿（启动日志会提示），换一个不会触发的站点即可。

    节点只接受与本机时间相差 120 秒以内的 REALITY 握手（reality_max_time_diff），重放的握手当作陌生连接处理。客户端时间不准会连不上，节点日志会写出相差的秒数。

    Vision 流控¶

    VLESS 节点的流控选 xtls-rprx-vision，传输方式选 tcp，安全性选 TLS 或 REALITY。这是最常用、最快的 VLESS 配置：

    面板字段 填
    传输方式 tcp
    安全性 REALITY（或 TLS）
    流控 xtls-rprx-vision

    VLESS Encryption¶

    VLESS 节点开启加密（ML-KEM-768 + X25519，含 0-RTT），面板里填服务端串 decryption（用 xray vlessenc 生成），客户端用对应的 encryption 串。可以不开 TLS 直接跑在 TCP 上，也可以和 Vision、TLS、REALITY 叠加。

    PPanel 只有开关、不下发服务端串，开了加密的 PPanel 节点起不来，日志说明原因，面板里关掉即可。

    Naive¶

    节点协议选 Naive，TLS 必须开（证书设置同其他 TLS 协议），传输用 TCP，不能用 REALITY。客户端用 NaïveProxy 或 sing-box 的 naive 出站，用户名和密码都填用户的 UUID。

    密码不对、不带填充的连接和其他任何请求，看到的都是一个普通网站，不会收到代理认证提示。只支持 HTTP/2，不支持 QUIC（HTTP/3）。UDP 走 sing-box 的 UDP over TCP。

    Shadow TLS（内置，无需额外部署）¶

    Shadowsocks 节点的插件选 Shadow TLS，插件选项填：

    host=伪装域名;password=密码;version=3

    面板里「连接端口」和「服务端口」填同一个端口。kaze 内置 Shadow TLS v3，不需要另外运行 shadow-tls 程序，也不用多占一个端口——其它后端通常要在 Shadowsocks 前面再挂一个 shadow-tls 进程并打通两个端口。

    Snell¶

    支持 Snell v1、v2、v3，三个版本在同一个端口上同时可用，节点不用选版本；UDP 需要客户端填 version=3。可选 simple-obfs 混淆（http / tls）。Snell v4 / v5 是另一套不公开的协议，不支持。

    每个用户的 PSK 就是面板发给他的 Shadowsocks 密码（Xboard 里即用户 UUID），流量、限速、设备数和其它协议一样按用户统计。

    面板这样下发：

    面板 做法
    有 Snell 节点类型 直接建 Snell 节点；version 不填按 3，混淆填 http / tls
    没有 Snell 节点类型 插件名能自由填写的面板：建一个 Shadowsocks 节点，插件填 snell，插件选项按需填 version=3;obfs=http;obfs-host=example.com（不要混淆就留空）。加密方式随便选，不会用到

    Note

    原版 Xboard 没有 Snell 节点类型，Shadowsocks 的插件又是固定下拉框，填不进 snell，这时请用本地模式搭 Snell。

    第二种做法下，面板给用户的订阅仍是一条 Shadowsocks 节点，客户端里要按 Snell 手动填，或由面板侧改写订阅。这种节点的授权按 Shadowsocks 计。

    客户端填法（PSK 换成该用户的密码）：

    节点名 = snell, 服务器地址, 端口, psk=用户的PSK, version=3

    开了混淆时在后面加 , obfs=http, obfs-host=example.com。

    - {name: 节点名, type: snell, server: 服务器地址, port: 端口, psk: 用户的PSK, version: 3, udp: true}

    开了混淆时加 obfs-opts: {mode: http, host: example.com}。

    用户很多的节点

    Snell 协议里没有用户标识，节点靠逐个试 PSK 认出用户。来过的 IP 和近期活跃的用户会优先试，通常一次就中；只有全新的连接才需要全表查找，耗时随用户数增长——单核参考值约为每 1000 个用户 20 毫秒。超过 1000 个用户时节点日志和 kaze check 会提示。几千人的大节点建议改用其它协议，或把用户分到多个 Snell 节点。

    TLS 证书¶

    Trojan、AnyTLS、Hysteria2、TUIC、Naive，以及开了 TLS 的 VLESS / VMess / SOCKS5 / HTTP 都需要证书（用 REALITY 的不需要）。最简单的做法：

    1 把域名（如 node1.example.com）解析到服务器 IP；

    2 面板节点的「服务器名称 SNI」填这个域名，证书模式选 http（Xboard：高级协议配置 → TLS）；

    3 保证服务器 80 端口能从公网访问，kaze 会自动申请证书并续期。不选证书模式时用的是自签证书。

    80 端口用不了、或者想用泛域名证书，用 DNS 验证；已经有证书文件也可以直接用。详见 TLS 证书。
