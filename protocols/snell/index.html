    Snell¶

    Snell 是 Surge 使用的轻量加密代理协议，Surge 和 mihomo / Clash.Meta 都支持，不需要域名和证书。kaze 支持 v1、v2、v3，三个版本在同一个端口上同时可用。主要给已经在用 Surge 的用户；面板支持和客户端覆盖都不如 Shadowsocks，新搭节点没有特别理由时用 Shadowsocks 更省事。

    推荐组合¶

    • 首选：Snell v3，不加混淆。客户端填 version=3，TCP 和 UDP 都能用（UDP 只有 v3 支持）。
    • 需要 HTTP / TLS 外观时：加 simple-obfs，http 或 tls 模式。

    Snell v4 / v5 是另一套没有公开说明的协议，不支持。

    面板里怎么填¶

    kaze 支持两种下发方式：

    面板 做法
    有 Snell 节点类型 直接建 Snell 节点；版本不填按 3（v1~v3 同时提供），混淆填 http / tls 或不填
    没有 Snell 节点类型 建一个 Shadowsocks 节点，插件填 snell，插件选项按需填 version=3;obfs=http;obfs-host=example.com（不要混淆就只写 version=3 或留空）。加密方式不会用到；建议选经典加密（如 aes-128-gcm），这样面板显示给用户的密码就是 PSK

    每个用户的 PSK 就是面板发给他的 Shadowsocks 密码（Xboard 里即用户 UUID）。流量、限速、设备数和其它协议一样按用户统计。

    Xboard 没有 Snell 节点类型。kaze 认「Shadowsocks 节点 + 插件 snell」的写法，但 Xboard 后台的插件是固定下拉框（None、Simple Obfs、V2Ray Plugin、Gost Plugin、Shadow TLS、ResTLS、KCPTun），里面没有 snell，在界面上选不出来。

    所以用 Xboard 时，Snell 节点只能在插件名可以自由填写的面板版本上这样建；否则用本地模式单独跑 Snell。

    V2board 没有 Snell 节点类型，Shadowsocks 节点也没有插件字段，不支持。

    如果你的 V2board 加了 Snell 节点类型，节点配置写 server_type=snell，面板下发的版本和混淆照常生效。

    kaze 读取 PPanel 里 Shadowsocks 协议的插件字段，插件为 snell 时按 Snell 提供，插件选项写法同上表。PPanel 后台能否填这个插件名，以你的版本为准。

    type=local
server_type=snell
port=8443
users=alice:psk1,bob:psk2
# 可选：simple-obfs 混淆
#plugin=obfs
#plugin_opts=obfs=http;obfs-host=www.bing.com
    键 说明
    server_type snell
    port 监听端口（只用 TCP）
    users 名字:PSK，逗号隔开，每个用户一个 PSK，不能重复。客户端的 psk 填对应的那串
    plugin / plugin_opts 可选。混淆：plugin=obfs + plugin_opts=obfs=http（或 obfs=tls），可加 obfs-host=；也可以 plugin=shadow-tls + plugin_opts=host=伪装域名;password=密码;version=3

    Snell 只有 PSK：不能写 cipher=、server_key=、tls=、network=，写了会在启动时报错。运行 kaze check 会打印这个节点给客户端的要点（提供 v1~v3、UDP 要 v3、混淆模式、PSK 是 users 里的密钥）。

    节点配置¶

    接面板时节点只写面板信息，不需要 TLS 证书：

    type=xboard
node_id=1
panel_url=https://panel.example.com
panel_key=通讯密钥

    V2board、PPanel 要加 server_type：面板里是 Snell 节点类型时写 snell；用 Shadowsocks 节点带插件 snell 时写 ss。防火墙放行这个端口的 TCP 即可，Snell 的 UDP 也走这条 TCP 连接。

    用 Shadowsocks 节点下发时，启动日志 listening 一行的 transport 会写 snell (carried by a Shadowsocks node)，可以确认节点按 Snell 在跑。

    用户很多的节点

    Snell 协议里没有用户标识，节点靠逐个试 PSK 认出用户。来过的 IP 和近期活跃的用户会优先试，通常一次就中；只有全新的连接才需要全表查找，耗时随用户数增长。超过 1000 个用户时节点日志和 kaze check 会提示。几千人的大节点建议改用其它协议，或把用户分到多个 Snell 节点。

    客户端怎么连¶

    Xboard 的订阅里没有 Snell 格式；用 Shadowsocks 节点下发时，订阅里是一条 Shadowsocks 节点，不能直接用。客户端里按 Snell 手动填（PSK 换成该用户的密码）：

    节点名 = snell, 服务器地址, 端口, psk=用户的PSK, version=3

    开了混淆时在后面加 , obfs=http, obfs-host=example.com（或 obfs=tls）。

    - {name: 节点名, type: snell, server: 服务器地址, port: 端口, psk: 用户的PSK, version: 3, udp: true}

    开了混淆时加 obfs-opts: {mode: http, host: example.com}。

    要用 UDP，客户端必须填 version=3；v1、v2 只有 TCP。

    常见问题¶

    日志里出现「Snell version 4 is not supported」（或 5） → 面板或插件选项里写了 v4 / v5，这是另一套不公开的协议 → 节点和客户端都改成 version=3。

    日志里出现「Snell runs directly on TCP, not over ws」 → 节点设了 WebSocket 等传输 → 传输改为 TCP；要外观用 simple-obfs。

    日志里出现「Snell obfs mode "..." is not supported; use http or tls, or none」 → 混淆模式写错 → 只能是 http、tls 或不填。

    日志里出现「plugin "..." is not supported for Snell; use obfs or shadow-tls, or none」 → 本地模式或 Snell 节点类型上写了不支持的插件 → 改成 obfs、shadow-tls，或去掉。

    日志里出现「this Snell node has ... users, more than 1000」 → 用户多，新连接的全表查找占 CPU → 所有用户照常可用；负载明显时把用户分到多个节点，或改用 Shadowsocks 2022 等能直接认出用户的协议。

    日志里出现「snell has no cipher= or server_key=」 → 本地模式的 Snell 节点写了 Shadowsocks 的设置 → 删掉 cipher 和 server_key，PSK 写在 users 里。
