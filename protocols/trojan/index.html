    Trojan¶

    Trojan 把代理流量放在一条普通的 TLS 连接里，用户只用一个密码认证，对外看起来就是一台 HTTPS 网站。它必须跑在 TLS（或 REALITY）上，协议本身很简单、速度快，客户端普遍支持；代价是用 TLS 时要准备一个解析到节点的域名和证书。不想管域名证书时用 Trojan + REALITY，或直接选 VLESS + REALITY。

    推荐组合¶

    • 首选：TCP + TLS，证书由 kaze 自动申请。最简单、兼容最好。
    • 备选：WebSocket / gRPC + TLS。要套 CDN 时用。
    • 不想要域名时：TCP + REALITY。不需要证书，客户端要支持 Trojan + REALITY；只有 Xboard、PPanel 和本地模式能这样配。

    REALITY 只能配 tcp、grpc、h2、xhttp，不能配 ws / httpupgrade。

    面板里怎么填¶

    节点管理 → 添加节点 → 选 Trojan。节点名称、权限组、节点地址、连接端口 / 服务端口、倍率和其它协议一样填。协议相关的字段：

    面板字段 填什么
    安全性 TLS（默认）或 Reality。Trojan 没有「无」
    传输协议 推荐 TCP；也可选 Websocket、gRPC、HTTP/2、HttpUpgrade、XHTTP，路径、serviceName 等在旁边的设置按钮里填
    客户端指纹 (uTLS) 可选，只写进订阅给客户端用，节点不看
    ECH 不支持，保持关闭

    安全性选 TLS 时：

    面板字段 填什么
    服务器名称指示(SNI) 节点的域名（要解析到这台服务器），也是申请证书用的域名。节点地址填同一个域名最省事
    允许不安全? 证书正常时保持关闭；用自签证书时才打开
    证书 在「高级设置 → 高级协议配置 → TLS」页签选证书模式，一般选 http-01 (ACME)，要求服务器 80 端口能从公网访问；见 TLS 证书

    安全性选 Reality 时：

    面板字段 填什么
    伪装站点(dest) 一个支持 TLS 1.3 的大网站域名，如 www.microsoft.com；客户端握手里也发这个名字
    端口(port) 伪装站点的端口，默认 443
    私钥(Private key) / 公钥(Public key) 点私钥输入框右边的钥匙按钮一起生成；没有按钮时在服务器上运行 kaze -reality-keypair
    Short ID 点刷新按钮生成，或填偶数位（最多 16 位）十六进制，可留空

    多路复用在「高级设置 → 高级协议配置 → 多路复用」页签，见协议与传输 → 多路复用。

    节点管理 → 添加节点 → Trojan。节点配置里要写 server_type=trojan。协议相关的字段：

    面板字段 填什么
    服务器名称指示(sni) 节点的域名
    允许不安全 证书正常时选「否」
    传输协议 tcp、ws、grpc 等

    V2board 的 Trojan 节点不下发安全性设置，节点一律用 TLS，不能用 REALITY。证书由节点自动申请或自签：面板不下发证书模式，要在节点配置写 cert_mode=http 和 cert_domain=节点域名，见节点配置。V2board 里 v2node 类型的节点看对接 V2board（v2node 节点）。

    在服务器里启用 Trojan 协议，设端口。节点配置里 server_type 要包含 trojan。

    • 安全：TLS 或 Reality；选 none 时节点照样按 TLS 运行。
    • TLS 时 SNI 填节点域名，证书模式选 http 或 dns 由节点自动申请；选 file 时在节点配置填 cert_file、key_file。
    • Reality 时 SNI 填伪装站点的域名；Reality 服务器地址 / 端口填握手借用的站点；再填私钥和 Short ID。
    • 传输：tcp、websocket、grpc、httpupgrade、xhttp、h2。
    • ECH 不支持，保持关闭。

    TLS（自动申请证书）：

    type=local
server_type=trojan
port=443
users=alice:密码1,bob:密码2
server_name=node1.example.com
cert_mode=http
cert_domain=node1.example.com

    REALITY：

    type=local
server_type=trojan
port=443
users=alice:密码1,bob:密码2
security=reality
reality_private_key=kaze -reality-keypair 输出的私钥
reality_short_id=6af819e1
server_name=www.microsoft.com
    键 说明
    users 名字:密码，逗号隔开。客户端只填密码，名字只用于日志和统计；名字和密码都不能重复
    server_name TLS：节点的域名；REALITY：伪装站点域名
    security 不写就是 TLS（Trojan 总是 TLS）；写 reality 用 REALITY
    reality_private_key / reality_short_id / reality_dest REALITY 的私钥、Short ID、伪装站点地址（默认 server_name 的 443）
    network tcp（默认）/ ws / httpupgrade / grpc / h2 / xhttp
    path / service_name ws、httpupgrade、xhttp、h2 的路径；grpc 的服务名
    cert_mode / cert_domain TLS 证书，见 TLS 证书；不写时自签

    一键安装命令里的 users= 密码只用字母数字。更多见不接面板，直接搭节点。

    节点配置¶

    接面板时节点写面板信息；证书模式在面板里选：

    type=xboard
node_id=1
panel_url=https://panel.example.com
panel_key=通讯密钥
license_key=KZ-XXXX-XXXX-XXXX

    V2board 和 PPanel 要加 server_type=trojan（PPanel 的 node_id 是服务器 ID）。面板没有证书设置（如 V2board）时，在节点配置里加：

    cert_mode=http
cert_domain=node1.example.com
    • 证书来源、DNS 验证、已有证书文件的写法见 TLS 证书。什么都不选时用自签证书，客户端得开「允许不安全」。
    • 不是你用户的访问者（密码不对、浏览器、探测器）看到的是一个网站：默认是内置的小页面，可以用 fallback 交给本机真实网站、或用 fallback_dir 指定静态页面目录，见配置项速查表。
    • 前面有 nginx 等负责 TLS 时写 force_close_ssl=true，节点不再做 TLS。
    • REALITY 节点不需要证书，但只接受与本机时间相差 120 秒以内的握手（reality_max_time_diff）。

    启动后日志里 listening 一行的 transport 字段写出实际提供的组合，例如 tcp+tls、tcp+reality、tcp+tls+ws。

    客户端怎么连¶

    订阅会自动带上全部参数。手动配置时要填：

    项 填什么
    服务器 / 端口 节点地址和连接端口
    密码 用户的密码（Xboard / V2board 里是用户的 UUID；本地模式是 users 里的密钥）
    SNI TLS：节点域名；REALITY：伪装站点域名，另填公钥和 Short ID
    跳过证书验证 证书正常时关闭；自签证书才打开
    传输 和节点一致，ws 等要填相同的路径

    mihomo / Clash.Meta 示例（TCP + TLS）：

    - name: 节点名
  type: trojan
  server: node1.example.com
  port: 443
  password: 用户的密码
  sni: node1.example.com
  skip-cert-verify: false
  udp: true

    REALITY 时把 sni 换成伪装站点，并加上 reality-opts（public-key、short-id）。sing-box 对应 trojan 出站：password，tls 里 enabled: true、server_name。

    常见问题¶

    日志里出现「using a self-signed certificate; clients must allow insecure connections」 → 没有证书模式，节点用了自签证书，客户端默认会拒绝 → 面板里选证书模式（http-01 / dns-01），或节点配置写 cert_mode=http + cert_domain=；临时可以让客户端开「允许不安全」。

    日志里出现「trojan: not a trojan client」（log_level=debug 时在 handshake failed 一行） → 密码不对（用户被删、换了订阅、订阅过期），或是浏览器 / 探测器 → 让用户更新订阅；kaze log 里搜 users synced 看节点拉到了多少用户。

    日志里出现「REALITY works on TCP, gRPC, H2 or XHTTP; change the node's transport」 → REALITY 配了 WebSocket 或 HttpUpgrade → 传输改成 TCP；要 WebSocket 就把安全性换回 TLS。

    日志里出现「REALITY hello outside the clock window」 → 客户端或服务器时间偏差超过 120 秒，或有人在重放握手 → 校准服务器时间（timedatectl），让用户校准设备时间。

    日志里出现「server_type is trojan but panel node 3 is vless」（数字和协议随你的配置） → 节点配置写了 server_type，和面板里这个节点 ID 的实际协议对不上（Xboard 会告诉节点协议） → 对接 Xboard 时删掉 server_type，或改成和面板一致。

    日志里出现「ECH is enabled in the panel but not supported by this node」 → 面板开了 ECH → 关掉 ECH；要求 ECH 的客户端连不上。
