    Hysteria2¶

    Hysteria2 跑在 QUIC（UDP）上，客户端填了自己的带宽时按这个速率发送，丢包多的线路上比 TCP 类协议快得多。代价是要放行 UDP、要 TLS 证书，而有的网络会限速或封锁 UDP。密码不对的连接只会看到一个返回 404 的 HTTP/3 网站。

    只支持 Hysteria 2，不支持 Hysteria 1。

    推荐组合¶

    • 首选：Hysteria2 + 自动申请的证书，带宽留空。 证书让客户端正常校验，不用开「允许不安全」；带宽留空时节点用 BBR 探测线路速度，用户自己在客户端填了带宽的，按他填的速率发送。
    • 单个 UDP 端口被限速或封锁：加端口跳跃。 客户端在一段端口里轮换，见端口跳跃。
    • QUIC 流量被识别：开 Salamander 混淆。 报文看起来不再像 QUIC；客户端必须填同一个混淆密码，没填的连不上。

    面板里怎么填¶

    节点管理 → 添加节点 → 节点类型选 Hysteria。节点名称、权限组、节点地址、倍率和其他协议一样填。

    面板字段 填什么
    连接端口 / 服务端口 直连时填同一个，例如 443。要端口跳跃时连接端口填端口段（如 20000-30000），服务端口填节点监听的端口，节点配置还要写 hop_ports，见端口跳跃
    协议版本 V2。选 V1 节点起不来
    混淆 一般关。打开后「混淆实现」只有 Salamander；「混淆密码」点右边的刷新按钮生成
    服务器名称指示(SNI) 证书上的域名，一般就是节点地址
    允许不安全? 证书正常时关
    ECH 不要开，kaze 不支持
    上行宽带 / 下行宽带（Mbps） 留空则使用 BBR。Xboard 按用户的角度理解：上行是用户上传，节点把它作为上传上限告诉客户端；下行是用户下载，节点给每个客户端的发送速率不超过它
    Hop 间隔 (秒) 端口跳跃时客户端多久换一次端口，只写进订阅

    证书在「高级设置 → 高级协议配置 → TLS」里选证书模式，一般选 http，见 TLS 证书。

    节点管理里添加 Hysteria 节点，节点配置写 server_type=hysteria。

    面板字段 填什么
    HYSTERIA版本 2
    连接端口 / 服务端口 同 Xboard；端口跳跃时连接端口填端口段，节点配置写 hop_ports
    服务器名称指示(sni) 证书上的域名
    允许不安全 证书正常时选否
    混淆方式obfs 无，或 salamander
    混淆密码obfs_password 开了混淆时填，留空由面板生成
    上行带宽 / 下行带宽 V2board 按节点的角度理解：上行是节点发送带宽，下行是节点接收带宽。两个都留空或填 0 时，节点不管客户端填的带宽，一律用 BBR

    V2board 没有证书设置，证书在节点配置里设，见下方节点配置。

    在服务器的协议设置里启用 hysteria2，节点配置的 server_type 写 hysteria。

    • 端口、TLS 证书模式按 PPanel 的设置下发，证书模式见 对接 PPanel。
    • 混淆密码填了就开 Salamander，不填就不混淆。
    • 上下行带宽会下发给节点。
    • 端口跳跃范围会下发给节点，节点配置不用写 hop_ports。
    • ECH 不要开。
    type=local
server_type=hysteria
port=443
users=alice:密码1,bob:密码2
cert_mode=http
cert_domain=node.example.com
#obfs_password=混淆密码
#hop_ports=20000-30000
    • server_type=hysteria 就是 Hysteria2。
    • users：名字:密码，客户端只填密码。
    • cert_mode / cert_domain：自动申请证书，要求域名解析到本机、80 端口能从公网访问；其他方式见 TLS 证书。不写时用自签证书。
    • obfs_password：写了就开 Salamander 混淆。
    • hop_ports：端口跳跃的端口段。
    • 本地模式没有带宽设置：客户端填了带宽就按它填的发送，没填用 BBR。

    节点配置¶

    Xboard 不用写协议：

    type=xboard
node_id=1
panel_url=https://panel.example.com
panel_key=通讯密钥
license_key=KZ-XXXX-XXXX-XXXX

    V2board、PPanel 要加 server_type=hysteria（type 换成 v2board / ppanel）。

    节点配置里的证书设置优先于面板。面板里没设证书（V2board 就没有这个设置）时，在节点配置里写：

    cert_mode=http
cert_domain=node.example.com
cert_email=you@example.com

    要端口跳跃且面板是 Xboard / V2board 时，再加一行和面板连接端口一致的 hop_ports=20000-30000。

    QUIC 自带 TLS，force_close_ssl 对 Hysteria2 无效，前面不能放 nginx 卸载 TLS。云厂商安全组要放行节点端口的 UDP（端口跳跃放行整段）。

    多 IP 的服务器上，auto_out_ip=true 让用户从哪个本机 IP 连进来就从哪个 IP 出去，对这个协议同样有效（Windows 除外），见源进源出。

    客户端怎么连¶

    用订阅最省事。面板模式下密码是用户的 UUID。手动配置时要填：

    项 填什么
    服务器、端口 节点地址和连接端口
    密码 面板模式填用户 UUID；本地模式填 users 里的密码
    SNI 证书上的域名
    混淆 节点开了混淆时选 salamander，填同一个混淆密码
    带宽 可选，填用户线路的真实上下行 
    - name: 节点名
  type: hysteria2
  server: node.example.com
  port: 443
  password: 用户的密码
  sni: node.example.com
  # 开了混淆时：
  # obfs: salamander
  # obfs-password: 混淆密码
  # 端口跳跃时：
  # ports: 20000-30000

    {
  "type": "hysteria2",
  "tag": "节点名",
  "server": "node.example.com",
  "server_port": 443,
  "password": "用户的密码",
  "tls": { "enabled": true, "server_name": "node.example.com" }
}

    开了混淆时加 "obfs": {"type": "salamander", "password": "混淆密码"}。

    常见问题¶

    日志里出现「only Hysteria 2 is supported; panel node 1 is version 1」 → 面板里协议版本选的是 1 → 改成 2。

    日志里出现「Hysteria obfuscation "xxx" is not supported」 → 混淆方式不是 salamander → 面板里改成 salamander，或者关掉混淆。

    日志里出现「using a self-signed certificate; clients must allow insecure connections」 → 面板和节点配置都没设证书，用的是自签证书 → 按 TLS 证书 申请真证书，或让客户端开允许不安全。

    日志里出现「port hopping not set up; clients still reach the node's own port」 → 写转发规则的权限不够 → 给 CAP_NET_ADMIN（Docker 加 cap_add: NET_ADMIN），见端口跳跃。

    日志里出现「ECH is enabled in the panel but not supported by this node; clients that require ECH cannot connect」 → 面板里开了 ECH → 关掉。
