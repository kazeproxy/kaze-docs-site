    AnyTLS¶

    AnyTLS 跑在 TCP + TLS 上，客户端用密码登录，一条连接里同时承载多个代理连接，并按「填充方案」给开头的几个包加填充，用来打乱流量特征。和 Trojan 一样简单，多了填充和多路复用；UDP 走 UDP over TCP。

    必须有 TLS（或 REALITY），传输只能是 TCP。

    推荐组合¶

    • 首选：AnyTLS + TLS（自动申请的证书），填充方案用默认。 所有面板都支持，客户端兼容最好。
    • 没有域名：AnyTLS + REALITY。 不需要证书，探测者看到的是伪装网站。只有 PPanel 和本地模式能配；AnyTLS + REALITY 不是每个客户端都支持，先确认你的客户端认这个组合。没域名又要兼容所有客户端，用 VLESS + REALITY。

    面板里怎么填¶

    节点管理 → 添加节点 → 节点类型选 AnyTLS。节点名称、权限组、节点地址、连接端口 / 服务端口、倍率和其他协议一样填。

    面板字段 填什么
    服务器名称指示(SNI) 证书上的域名，一般就是节点地址
    允许不安全连接 证书正常时关
    ECH 不要开，kaze 不支持
    填充方案 点「使用默认方案」，或留空（节点按默认方案）。改了的话节点会把新方案告诉客户端，客户端不用跟着改

    Xboard 的 AnyTLS 节点只有 TLS，没有 REALITY 选项。证书在「高级设置 → 高级协议配置 → TLS」里选证书模式，一般选 http，见 TLS 证书。

    节点管理里添加 AnyTLS 节点，节点配置写 server_type=anytls。

    面板字段 填什么
    服务器名称指示(sni) 证书上的域名
    允许不安全 证书正常时选否
    编辑填充方案 不改就用默认方案

    V2board 的 AnyTLS 只有 TLS，没有证书设置，证书在节点配置里设，见下方节点配置。

    在服务器的协议设置里启用 anytls，节点配置的 server_type 写 anytls。

    • 安全选 TLS 或 REALITY。选 REALITY 时填伪装站点、私钥、Short ID，见协议与传输里的 REALITY 一节。
    • 传输保持 TCP。
    • 填充方案会下发给节点，不填用默认方案。
    • 证书模式见 对接 PPanel。ECH 不要开。

    TLS：

    type=local
server_type=anytls
port=443
users=alice:密码1,bob:密码2
cert_mode=http
cert_domain=node.example.com

    REALITY（不需要证书）：

    type=local
server_type=anytls
port=443
users=alice:密码1
security=reality
reality_private_key=kaze -reality-keypair 生成的私钥
reality_short_id=6af819e1
server_name=www.microsoft.com
    • users：名字:密码，客户端只填密码。
    • cert_mode / cert_domain：自动申请证书，要求域名解析到本机、80 端口能从公网访问；其他方式见 TLS 证书。不写时用自签证书。
    • security=reality：server_name 是一个支持 TLS 1.3 的大网站；kaze check 会打印客户端要填的公钥、Short ID 和服务器名称。
    • 本地模式没有填充方案设置，用默认方案。

    节点配置¶

    Xboard 不用写协议：

    type=xboard
node_id=1
panel_url=https://panel.example.com
panel_key=通讯密钥
license_key=KZ-XXXX-XXXX-XXXX

    V2board、PPanel 要加 server_type=anytls（type 换成 v2board / ppanel）。

    用 TLS 而面板里没设证书（V2board 就没有这个设置）时，在节点配置里写：

    cert_mode=http
cert_domain=node.example.com
cert_email=you@example.com

    不是 AnyTLS 客户端的访问（浏览器、扫描器、密码错误的连接）看到的是一个网站，默认是内置的小页面，可以用 fallback 换成自己的网站，见配置项速查表。REALITY 节点上这些访问交给伪装站点。

    客户端怎么连¶

    用订阅最省事。面板模式下密码是用户的 UUID。手动配置时要填：

    项 填什么
    服务器、端口 节点地址和连接端口
    密码 面板模式填用户 UUID；本地模式填 users 里的密码
    SNI 证书上的域名
    填充方案 不用填，节点会告诉客户端 
    - name: 节点名
  type: anytls
  server: node.example.com
  port: 443
  password: 用户的密码
  sni: node.example.com
  udp: true

    {
  "type": "anytls",
  "tag": "节点名",
  "server": "node.example.com",
  "server_port": 443,
  "password": "用户的密码",
  "tls": { "enabled": true, "server_name": "node.example.com" }
}

    Xboard 的 sing-box 订阅

    Xboard 给 sing-box 的 AnyTLS 订阅只声明了 ALPN h3。节点默认放行这种客户端；打开 strict_alpn=true 后它们会连不上，用 Xboard 的节点不要开。

    常见问题¶

    日志里出现「AnyTLS runs over TLS on plain TCP; check the node's transport and security settings」 → 面板里给节点选了 TCP 以外的传输（WebSocket、gRPC 等） → 传输改回 TCP。

    日志里出现「using a self-signed certificate; clients must allow insecure connections」 → 没设证书，用的是自签证书 → 按 TLS 证书 申请真证书，或让客户端开允许不安全。

    日志里出现「ECH is enabled in the panel but not supported by this node; clients that require ECH cannot connect」 → 面板里开了 ECH → 关掉。

    kaze check 报「security=reality needs reality_private_key (make a pair with: kaze -reality-keypair; the public key goes to the clients)」 → 本地模式开了 REALITY 但没写私钥 → 运行 kaze -reality-keypair，私钥写进 reality_private_key，公钥给客户端。
