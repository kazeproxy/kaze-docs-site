    SOCKS5 与 HTTP 代理¶

    SOCKS5 和 HTTP 代理是最通用的两种代理协议，几乎所有软件和系统都能直接用，适合自用出口、内网中转、给程序挂代理。它们本身不加密：不开 TLS 时密码和流量都是明文，也很容易被识别，不适合直接给机场用户翻墙用。SOCKS5 转发 TCP 和 UDP；HTTP 代理只转发 TCP。

    推荐组合¶

    • 首选：SOCKS5 + TLS。 开 TLS 后密码和流量不再明文；TCP、UDP 都能转发。客户端要支持 SOCKS over TLS（如 mihomo、Surge、Shadowrocket）。
    • 只给自己或内网用： 本地模式的 SOCKS5 可以免密码，但一定要用防火墙限制来源 IP（见下方本地模式）。
    • HTTP 代理： 只有软件只认 HTTP 代理时才用，同样建议开 TLS。

    面板里怎么填¶

    节点管理 → 添加节点 → 节点类型选 SOCKS 或 HTTP。节点名称、权限组、节点地址、连接端口 / 服务端口、倍率和其他协议一样填。

    SOCKS：没有其他要填的。Xboard 的 SOCKS 节点没有 TLS 选项，所以是明文的，节点启动日志会提示密码明文。

    HTTP：

    面板字段 填什么
    TLS 选「支持」开 TLS（推荐）；「不支持」为明文
    服务器名称指示(SNI) 开了 TLS 时填节点的域名，证书按这个名字申请和出示
    允许不安全连接 证书正常时不要开

    HTTP 开了 TLS 时的证书：高级协议配置 → TLS 页签 → 证书模式选 http，填证书域名；其他方式见 TLS 证书。

    订阅里用户名和密码都是用户的 UUID，节点只核对密码。Shadowrocket 格式的订阅只带 SOCKS 节点，不带 HTTP 节点。

    不支持：V2board（含 wyx2685 版的 v2node 节点）没有 SOCKS、HTTP 节点类型。

    服务器的协议列表里启用 SOCKS 或 HTTP，节点配置写 server_type=socks 或 server_type=http。安全可选 TLS（填 SNI 和证书模式）或 REALITY；传输只能是 TCP。

    type=local
server_type=socks            # 或 http
port=1080
users=alice:密码1,bob:密码2
tls=true
cert_mode=http
cert_domain=node1.example.com
    • server_type：socks（也可写 socks5）或 http。
    • port：监听端口。SOCKS5 的 UDP 也用这个端口号（UDP），防火墙两个都要放行。
    • users：名字:密钥，逗号隔开。密钥就是客户端的密码；用户名节点不核对，客户端填名字或随便填都行。名字和密钥都不能重复。
    • tls=true（或 security=tls）+ 证书设置：开 TLS，见 TLS 证书。不写证书设置时用自签证书，客户端要允许不安全连接。不开 TLS 时启动日志会提示密码明文。
    • 也可以用 security=reality（写法见不接面板，直接搭节点），但要客户端支持。
    • 传输只能是 TCP，不要写 network=。

    SOCKS5 免密码：不写 users（或写成 users=）。

    type=local
server_type=socks
port=1080
    • 客户端选「无认证」直接连；客户端填了用户名密码也能连，填什么都行。
    • 所有连接算作同一个匿名用户（anonymous），流量统计和限速按这一个用户算。
    • 启动日志和 kaze check 都会提示这个节点不需要密码。
    • 只有本地模式的 SOCKS5 能免密码。HTTP 代理必须写 users；接面板的节点，用户由面板下发。

    免密码的端口要用防火墙限制来源 IP

    能连到这个端口的人都能拿它当代理。用防火墙只放行你自己的 IP（TCP 和 UDP 都要设），或用 listen= 只监听内网地址，例子见不接面板，直接搭节点里的 ufw 写法。

    节点配置¶

    Xboard（协议由面板告知，不用写 server_type）：

    type=xboard
node_id=1
panel_url=https://panel.example.com
panel_key=通讯密钥

    PPanel 要写 server_type=socks 或 server_type=http，node_id 填服务器 ID。

    开了 TLS 的节点要证书：在面板里选证书模式，或在节点配置写：

    cert_mode=http
cert_domain=node1.example.com

    详见 TLS 证书。前面有 nginx 等负责 TLS 时，节点写 force_close_ssl=true，此时不会提示明文。

    开了 TLS 时，不是代理客户端的访问者（比如直接用浏览器打开）看到的是一个网站页面，可以用 fallback 换成自己的网站，见配置项速查表。

    客户端怎么连¶

    订阅一般自动带上。手动配置时：

    项 填什么
    服务器 / 端口 节点地址和端口
    用户名 面板用户：自己的 UUID；本地模式：随便填（免密码时可以不填）
    密码 面板用户：自己的 UUID；本地模式：users 里的密钥
    TLS 和节点一致；开了 TLS 时 SNI 填节点域名 
    - {name: 节点名, type: socks5, server: node1.example.com, port: 1080, username: 用户名, password: 密码, tls: true, udp: true}
- {name: 节点名, type: http, server: node1.example.com, port: 8080, username: 用户名, password: 密码, tls: true}

    节点没开 TLS 时去掉 tls: true；自签证书加 skip-cert-verify: true。

    节点名 = socks5-tls, node1.example.com, 1080, 用户名, 密码, sni=node1.example.com, udp-relay=true
节点名 = https, node1.example.com, 8080, 用户名, 密码, sni=node1.example.com

    没开 TLS 时类型写 socks5 / http，去掉 sni=。

    HTTP 代理不转发 UDP；需要 UDP（游戏、语音、QUIC）时用 SOCKS5。

    常见问题¶

    日志里出现「a proxy without TLS sends its password and traffic in the clear; turn on TLS for the node unless something in front of it encrypts」 → 节点没开 TLS，密码和流量明文传输。 → 开 TLS（Xboard 的 HTTP 节点 TLS 选「支持」；本地模式写 tls=true 并配证书）。前面已有负责加密的代理时写 force_close_ssl=true。

    日志里出现「SOCKS5 without authentication (users= is empty): anyone who can reach the port can use it; limit who can with a firewall, or set users= to require a password」 → 本地模式的 SOCKS5 没写 users，节点免密码。 → 确实要免密码就用防火墙限制来源 IP；否则写上 users。

    kaze check 报「users is required for a local node, e.g. users=alice:secret1,bob:secret2 (only a socks node may leave it out, to serve without a password)」 → 本地模式的 HTTP 代理（或其他非 SOCKS5 协议）没写 users。 → 写上 users；只有 SOCKS5 能免密码。

    日志里出现「socks runs on plain TCP, with or without TLS; change the node's transport」（HTTP 节点是 http runs on …） → 给节点设了 WebSocket / gRPC 等传输。 → 传输改回 TCP；本地模式删掉 network=。

    日志里出现「socks5: authentication failed」或「http proxy: authentication failed」（log_level=debug 时，在「handshake failed」这一行里） → 密码不对。面板用户的密码是 UUID，本地模式是 users 里的密钥（不是名字）。 → 连续失败太多次时会出现「address banned after repeated authentication failures」，这个 IP 会被暂时封禁，见用户限制与风控。
